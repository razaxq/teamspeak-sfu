# TeamSpeak SFU

[English](README.md) | **简体中文**

一个实验性的自部署 SFU，让**未修改的官方 TeamSpeak 6 客户端**通过服务器共享屏幕画面。

**当前状态：官方客户端之间的共享画面已由实际用户确认可观看。共享声音不可用，观看端没有共享音量控件。服务端仅支持 Linux ARM64 和指定的 TeamSpeak 服务端版本。**

> **建议使用人群：具备软件开发经验，或熟悉使用 Codex 辅助开发、部署和排错的人。** 本项目仍处于实验阶段，需要阅读说明、配置 Linux 服务器，并排查版本兼容或网络问题，暂不适合作为面向非技术用户的一键安装产品。使用 Codex 辅助操作时，也需要审阅改动并在自己的服务器上验证结果。

[自行部署指南](docs/SELFHOST.zh-CN.md) · [下载预览版](https://github.com/razaxq/teamspeak-sfu/releases) · [发布说明](RELEASE_NOTES.zh-CN.md) · [反馈问题](https://github.com/razaxq/teamspeak-sfu/issues)

## 项目做什么

SFU（Selective Forwarding Unit，选择性转发单元）接收发布者的媒体数据，再转发给观看者。本项目结合 TeamSpeak 服务端扩展、原生信令和 mediasoup 媒体服务，在实验部署中打通官方客户端的 **Server / 服务器** 屏幕共享模式。

部署者在自己的服务器上运行服务端组件。发布者和观看者使用原版 TeamSpeak 客户端，无需修改或替换客户端；客户端也不需要公网 IP。

**必须部署本项目配套的实验 TeamSpeak 服务端。仅在任意现有服务器的 SFU Endpoint 中填入地址，不能获得相同功能。** 部署会创建独立服务器实例，使用自己的凭据和数据卷。

## 功能与当前状态

| 能力 | 状态 |
| --- | --- |
| 官方客户端共享入口和正在分享图标 | 已实现 |
| 开播/停播通知及观看审批 | 已实现 |
| 原版官方客户端之间共享屏幕画面 | 已由用户确认 |
| 共享声音及观看端共享音量控件 | **不可用** |
| 普通 TeamSpeak 语音聊天 | 用户反馈正常，与共享声音是不同链路 |
| 普通已连接用户开播 | 支持，无需管理员组权限 |
| 自定义公网地址、端口、容器、数据卷和状态目录 | 已实现 |
| 固定服务端版本校验及本地编译扩展 | 已实现 |
| 正常重启保留凭据和数据 | 已通过独立实例验证 |
| x86_64 服务端及其他客户端/服务端版本 | 尚不支持或未经验证 |
| 大规模使用和长期无人值守运行 | 未经验证 |

已验证的官方客户端为 **Windows TeamSpeak 6.0.0-beta4.1，内部版本号 1779880475**，不能据此推断其他版本兼容。

媒体核心包含自动化测试和浏览器音视频测试，但这些测试**不能证明官方客户端共享声音可用**。具体验证范围见[发布说明](RELEASE_NOTES.zh-CN.md)。

## 工作原理

| 组件 | 作用 |
| --- | --- |
| 固定版本 TeamSpeak 服务端及本项目 C 扩展 | 接入原生直播控制流程，并与 SFU 服务连接 |
| Node.js 原生信令服务 | 处理直播访问、发布/观看权限、观看审批和通知 |
| mediasoup | 接收并转发 WebRTC 媒体 |
| 原版 TeamSpeak 客户端 | 通过客户端界面发布屏幕和加入观看 |

扩展依赖特定 ARM64 服务端二进制布局。启动前会验证服务端 SHA-256，并在本地编译扩展。不要将固定镜像替换为 `latest`，也不要自动升级服务端镜像。

实验服务器中名为“SFU 服务”的连接负责原生分享通知，会占用一个连接名额，应保持在线。

## 部署要求

- 具有公网 IPv4 的 **Linux ARM64 / aarch64** 服务器。
- root 权限、systemd、**rootful Podman**、iptables、GCC 和 **Node.js 22+**。
- 若 mediasoup 需要本地编译 worker，还需要 Python 3.10+、pip 和 C++ 编译器。
- A 记录直接解析到服务器的域名，或直接使用公网 IPv4。
- 能获取指定的上游 TeamSpeak 镜像和 npm 依赖。
- 建议使用已经验证的官方客户端版本，以便复现当前结果。

默认端口：

| 端口 | 协议 | 用途 |
| --- | --- | --- |
| 19987 | UDP | TeamSpeak 连接和语音 |
| 18344 | TCP | 原生 SFU WebSocket 信令 |
| 19125 | UDP、TCP | WebRTC 媒体 |
| 11022 | TCP，仅回环 | 内部 SSH Query，不向公网开放 |

当前部署使用 IPv4 直连和 Podman 默认桥接网络，不提供 WSS、TURN、IPv6、rootless 或反向代理部署方案。

## 开始部署

具体命令和配置请按**[完整自部署指南](docs/SELFHOST.zh-CN.md)**执行，流程如下：

1. 从 [Releases](https://github.com/razaxq/teamspeak-sfu/releases) 下载源码包，解压到 `/opt/ts6-native-sfu-lab`。
2. 安装系统依赖和 npm 运行依赖。
3. 复制示例配置，填写自己的公网域名/IP，阅读 TeamSpeak 服务端许可后设置接受。
4. 拉取固定镜像，运行预检查，验证二进制并编译扩展。
5. 开放云安全组/防火墙端口，安装 systemd unit 并启动服务。
6. 在 `status.json` 中确认就绪，再在服务器本地读取生成的连接信息和管理员权限密钥。

密码、权限密钥和状态由各自部署的服务器生成，仓库不包含通用登录凭据。

## 发布与观看

1. 双方连接实验 TeamSpeak 服务器，并进入同一频道。
2. 已连接服务器的普通用户即可开播，无需加入管理员组或使用管理员权限密钥。管理员密钥仅用于管理服务器。
3. 发布者打开屏幕共享，选择 **Server / 服务器**，开始直播。
4. 观看者通过分享图标加入；出现审批时，由发布者允许观看。

部署脚本会自动配置 SFU Endpoint，观看者不需要管理员权限。**本预览版的屏幕共享按仅有画面使用。**

原生 SFU 不再施加旧版的 8 个连接、4 路直播或 16 个观看名额上限。`viewer_limit=0` 表示 SFU 不设观看人数上限；发布者明确设置的正数观看人数限制仍会生效。凭据随当前 TeamSpeak 连接有效，不再一小时到期。断开连接、切换频道、凭据轮换或可信客户端目录失联仍会撤销访问。

TeamSpeak 自身仍有槽位配置及许可上限。[官方 Beta 服务端包含 32 个槽位](https://github.com/teamspeak/teamspeak6-server#readme)，通知服务占用其中一个，本版本不会绕过该限制。每个 TeamSpeak 连接仍对应一路直播，因为原生直播查询按发布者客户端 ID 定位。移除 SFU 配额不代表硬件容量无限，也不代表已通过大规模压测。

## 运维与限制

TeamSpeak 数据保存在 Podman 卷 `ts6-sfu-selfhost-data`，凭据和扩展状态保存在 `/var/lib/ts6-sfu-selfhost/`。应一同备份；正常重启会保留这些数据。不要把凭据、整个状态目录或未经审阅的日志上传到公开 issue。

部署脚本管理本实例的宿主机防火墙规则，正常停止时清理；不会配置云安全组。异常终止可能留下容器或防火墙规则，需要人工检查。详见[维护与排错](docs/SELFHOST.zh-CN.md#维护与排错)。

这是**社区实验项目，并非 TeamSpeak 官方产品**，预览版用于测试和收集反馈。共享声音、更多架构和版本支持、异常恢复、长时间运行稳定性仍需要完善。
